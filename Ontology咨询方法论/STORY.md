# Ontology 咨询方法论 · 30 页 STORY

## 一句话主张

**Ontology 不是一张新的图，而是让「数据 — 逻辑 — 行动 — 权限」四件事在同一层上被定义清楚；它是 AI 时代 4A 架构的新实践点。**

## 与前四册的关系

| 专册 | 核心命题 | 一句话 |
|---|---|---|
| DA | 先有治（标准/模型/分布），才有存 | 数据架构是枢纽 |
| BA | 能力是与组织解耦的稳定层 | 业务架构是基础 |
| AA | 应用数量增长是技术债主要来源 | 应用架构是载体 |
| TA | 不在单点技术上押注，在分层与标准上投资 | 技术架构是底座 |
| **Ontology** | **语义与动力学合一，才谈得上决策可执行** | **Ontology 是 4A 的汇流点** |

四层解决「看得见」，Ontology 解决「动得了」。

## Approach 七阶段（P04 核心）

1. 场景与决策定义 → 场景清单 + 决策卡
2. 数据探查与可用性评估 → 数据可用性报告 + 缺口清单
3. Object / Link 建模 → 对象模型画布 + 链接矩阵
4. Action / Function 与权限 → 动作清单 + 权限矩阵
5. 应用与 AI 消费 → 应用原型 + 场景验证记录
6. 运营闭环与写回 → 写回链路 + 审计日志抽样
7. 演进与治理 → 本体版本规范 + 变更评审机制

三条硬规则：先决策后对象；先单域后跨域；先读后写。
