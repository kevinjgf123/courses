# Agent 咨询方法论 · 30 页 STORY

## 一句话主张

**Agent 不是「会聊天的模型」，而是「有职权的角色」——它必须有明确的岗位、明确的授权边界、明确的停手条件，以及可被审计的决策链。**

## 与 Ontology 的关系（贯穿全册的第一主线）

Ontology 是**被调用的对象**，Agent 是**发起调用的角色**。三条硬边界：
1. Agent 的一切认知来自 Ontology，它自己不持有业务事实
2. Agent 的一切改变通过 Action Type，它自己直连任何外部系统都算越权
3. Agent 的一切权限是「以最终用户的身份」执行，它不是一个超级账号

## Approach 七阶段（P04 核心）

1. 场景与岗位定义 → 场景清单 + 岗位说明书
2. 本体与动作就绪度评估 → 就绪度报告 + 缺口清单
3. 上下文设计 → 上下文规格书（塞什么/多少/怎么压缩）
4. 工具与技能装配 → 工具装配表 + 技能目录
5. 权限与终止条件设计 → 权限矩阵 + 停手条件表
6. 评测集与试运行 → 评测集 + 试运行报告
7. 上线与演进治理 → 上线评审表 + 退役预案

三条硬规则：先单 Agent 后多 Agent；先只读建议后受限自主；先评估后扩量。
